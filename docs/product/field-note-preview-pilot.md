# Field note preview pilot

## Objective and audience

Help enterprise sales and revenue leadership hiring managers assess Kristen's judgment without requesting access. Pilot only: `/field-notes/multithreading`, the stakeholder preview and existing inquiry form. No homepage or navigation migration.

## Acceptance and evidence

- Public summary precedes a three-question framework and fictional guided map: implemented in the multithreading route.
- Desktop map nodes and mobile role buttons select one detail panel: implemented with native buttons, pressed states and visible focus. Browser QA remains required.
- Guided steps expose the economic-buyer gap and one next conversation; seller and leader views provide different coaching context.
- Request identifies the walkthrough automatically: allowlisted query resolved on the server, displayed in the form and included in the existing contact payload. Unit coverage tests known, unknown, repeated and unsafe identifiers and inquiry formatting.
- No automatic grant, protected download, private repository integration or promise of a completed playbook. Email delivery still depends on the existing contact service configuration; no real inquiry was sent during verification.
- Existing #method, #coaching, #research and #coverage-lab targets remain.

## Content ownership and publication

The private knowledge workspace remains the source for private methods and learning. The public portfolio presents deliberately reviewed excerpts. This pilot uses existing public-safe portfolio material; private playbook text is not copied, linked or fetched at runtime.

For later entries, prepare a public excerpt, verify each claim and its sharing permission, review it in a focused portfolio PR, then publish. Keep each public excerpt in one portfolio-owned record when a second entry makes shared rendering useful. Do not introduce a cross-repository runtime integration yet.

Public layer: problem, audience, concise approach, fictional example and related evidence. Deeper layer: a reviewed walkthrough or sanitized materials shared separately where available. Advertise a full playbook only once it exists and has an approved delivery path.

Removing detailed copy from this page reduces public depth; it does not retract content previously published or remove Git history. No claim of retroactive confidentiality is made.

## Next protected-delivery milestone

Before hosting full playbooks, establish verified identity, explicit resource grants, expiration/revocation, server-side authorization on every delivery path, private storage and tests for denied access. Do not ship full text in client bundles, public git, static payloads or obscured HTML. Existing access-policy helpers alone are not a deployed access system.
