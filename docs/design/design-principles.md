# Design principles and learning guide

1. **Hierarchy:** first screen must say who Kristen is and why her work matters. Test by hiding details and looking for the main message.
2. **Proximity:** group problem, role, actions, outcome in each case study. Different sections need consistent whitespace.
3. **Alignment:** maintain a defined content grid across cards, typography and navigation.
4. **Contrast:** create clear distinctions between primary actions, body copy, and secondary labels; test actual token pairs.
5. **Consistency:** share tokens and components across Work and Side Quests, with only controlled differences in tone.
6. **Affordance and feedback:** links and buttons should look actionable; include hover, focus-visible, loading/error states when relevant.
7. **Accessibility:** WCAG 2.2 AA target; semantic headings, keyboard order, adequate contrast, reduced-motion support.
8. **Progressive disclosure:** lead with outcomes; let detail pages show architecture and implementation evidence.
9. **Responsive first:** test narrow screens early, then expand to desktop.
10. **Honest evidence:** no invented testimonials, user-study findings or business metrics.

## Exercise template
For each change: name the principle → cite current observation → sketch two solutions → write tradeoffs → test at mobile/desktop → record learning.
