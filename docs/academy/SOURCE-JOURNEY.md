# Guided journey: Source verification

Route: `/ai-academy/journeys/source-verification` (feature branch only, not released).

## Learning objective
The learner can distinguish a claim from a supporting source, avoid overclaiming from limited evidence, and explain one verification question for a GTM or cybersecurity scenario.

## Four-part experience
1. Learn — source, evidence, claim, hypothesis; worked example and misconceptions.
2. Practice — fictional scenario; classify a claim and identify which supplied source to inspect.
3. Feedback — independently grade claim and source selections with explicit explanations; successful answers unlock transfer.
4. Apply — connect the concepts to Account Signal Engine's stored sources and evidence; learner writes a verification question. Completion is explicitly session-only.

## Acceptance criteria
- Learner can restart, correct answers, and choose among three synthetic cases.
- One incorrect choice cannot unlock Apply.
- Changing scenarios clears old assessment and reflection state.
- Semantic form labels, visible focus, status updates, and small-screen layout are reviewed.
- No live vendor facts are asserted; no personal information persists or reaches a server.
- Linked portfolio application is for education only; no automatic claim approval or CRM updates.

## Verification
Before merge run `npm test`, `npx tsc --noEmit`, `npm run lint` and `npm run build`, followed by keyboard and mobile testing.

## Curriculum alignment
Source verification lesson → Source Detective → source evidence → account research / future framework mapping.
