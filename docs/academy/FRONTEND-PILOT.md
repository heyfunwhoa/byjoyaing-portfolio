Status: runnable comparison completed and the single lesson implemented with existing components. Not merged and not deployed.
Reviewed: 2026-10-30.
Owner: byjoyaing-portfolio. Tracking: [KRU-176](https://linear.app/krusty/issue/KRU-176), [KRU-177](https://linear.app/krusty/issue/KRU-177), [KRU-178](https://linear.app/krusty/issue/KRU-178).
Scope: `frontend-building-blocks` only.

## Decision

**Adapt the existing Academy components. Defer Fumadocs.**

Fumadocs UI 16.17.9 can render the same section titles, and its documented peers match this repo's Next.js 16.4.3 and React 19.3.1. The trial did not show a benefit that outweighs a second theme, a documentation provider, or 64 added lockfile packages. The lesson's checks, feedback, reset, local notes and next-step selection are Academy behavior. `Steps` does not provide them.

This is the KRU-176 recommendation. KRU-177 uses it for this one lesson. It is not approval to adopt Fumadocs later, and it is not a mastery or release claim. KRU-178 still owns learner validation and release evidence.

## Lesson implementation

The guided programming component is a modal for two programming slugs and scores a session total. The CMS lab reviews a choice only after a separate button. Neither composition is the frontend sequence, so this lesson adapts their native radios, reset, polite status and tokenized panel instead of generalizing either one.

| File                                        | Treatment                                                                                                                     |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `lib/ai-academy.ts`                         | Stable `frontend-building-blocks` record kept, including the existing check, exercise and sources                             |
| `lib/academy/lesson-guidance.ts`            | Empty prerequisites, optional Programming Foundations link, and the editorial project-card practice link kept                 |
| `components/ai-academy/academy.tsx`         | One conditional mount before the shared knowledge check. Account controls from PR #234 sit after that check and are untouched |
| `lib/academy/frontend-lesson.ts`            | Objective, vocabulary, example, practice, two checks, transfer rubric and next steps                                          |
| `components/ai-academy/frontend-lesson.tsx` | The only new renderer, mounted for this slug                                                                                  |
| `content/academy/lessons/`                  | No new editorial record                                                                                                       |
| `docs/design/component-adoption.md`         | Adoption note for this call site                                                                                              |

The rendered order is objective, section links, vocabulary, worked example, guided practice, two checks, independent notes, then next step. The catalog exercise, practice link, single knowledge check, review button, companion and sources remain below it.

Section links move focus to the section. They do not create a durable lesson URL. Lesson choice stays in memory.

Practice and both checks use labeled radio groups. The selected choice's explanation stays visible, including when it is wrong. Reset clears that group. The verification example stays hidden until requested. Notes are component state only: they are not submitted, saved or scored. A correct choice does not press "Mark as reviewed".

Next step uses the existing `selectLesson` function. Design Lab stays on the frontend path. CMS fundamentals leaves that path because it is not one of its lessons.

## Responsive and keyboard contract

- Phone: one reading column, the existing lesson selector, wrapping section links and labels, stacked choices, at least 44px targets. The example source scrolls inside its box.
- Tablet: the same reading order. No second sidebar is required.
- Desktop: the existing catalog sidebar remains. The lesson stays one column.
- Keyboard: links move between sections, buttons run actions, radios are labeled, focus stays on the radio after it is selected, and feedback uses a polite status. No drag or hover-only meaning.
- Motion: none added. An answer does not scroll or advance.
- The code sample is selectable and scrolls inside its box.
